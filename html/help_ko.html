1. nodegram이란

nodegram은 노드로 프로그래밍하는 도구입니다.

Stick 노드를 Character 노드에 연결하기만 해도 캐릭터가 움직입니다.



• 스마트폰에서도 PC에서도 프로그래밍할 수 있습니다.

• 만든 게임을 다른 사람이 플레이하게 할 수 있습니다.
• nodegram은 웹에서 동작하므로 인터넷만 연결되어 있으면 어디서든 프로그래밍할 수 있습니다(nodegram 프로그램 하나의 용량은 사진 한 장 정도입니다).

노드 프로그래밍(Node Programming)이란
nodegram에는 더하기만 하는 노드, 숫자를 기억하는 노드, 키가 눌렸는지 확인하는 노드 등 40종류가 넘는 노드가 있습니다.
노드 프로그래밍은 여러 일꾼(노드)이 서로 정보를 주고받으며 하나의 큰 일을 해내는 방식입니다. 각 일꾼은 앞 사람에게서 값을 받아 자기 몫의 작은 일을 하고 결과를 넘겨줍니다. 모든 일꾼이 쉬지 않고 계속 일합니다.
반면 글로 쓰는 프로그래밍은 방식이 다릅니다. 한 명의 일꾼이 명령을 하나씩 읽으며 차례대로 처리합니다.

2. 시작하는 방법


슈팅 게임 만드는 법(2분)

nodegram에는 세 가지 화면이 있습니다.
프로그램을 짜는 NodeEditor
오브젝트를 배치하는 Layout
프로그램을 실행하는 Play 

입니다.

2-1. 노드 만들기(NodeEditor)

  • NodeEditor에서 배경(비어 있는 검은 부분)을 길게 누르면 “CREATE NEW NODE” 창이 열립니다.


  • 목록에서 원하는 노드를 고르면 NodeEditor에 만들어집니다.
  • 만들어진 노드를 길게 누르거나 더블클릭하면 세부 설정을 하는 Property 창이 열립니다.
    오브젝트의 색 같은 설정은 여기서 바꿉니다.
    OK 버튼은 없으며 바꾸는 즉시 반영됩니다. 오른쪽 위의 ×를 누르거나 창 바깥을 터치해 닫으세요.
    DUPLICATE는 노드를 복제하고 DELETE는 삭제합니다.
  • 노드를 드래그(터치한 채 움직이기)하면 위치를 옮길 수 있습니다.
  • 노드 오른쪽의 출력 단자에서 (다른 노드 왼쪽의) 입력 단자로 드래그하면 선이 연결됩니다. 연결되면 프로그램이 실행될 때 값이 그 선을 따라 빨간 단자에서 파란 단자로 흐릅니다.



  • 위쪽에 단자(자식 단자)가 있는 노드는 그곳에서 (다른 노드 아래쪽의) 부모 단자로 연결할 수 있습니다. 그러면 둘은 부모-자식 관계가 되어 부모가 움직일 때 자식도 함께 움직입니다.
    예를 들어 플레이어가 총을 쏜다면 총알이 나가는 곳을 자식으로, 플레이어를 부모로 삼습니다.

2-2. 오브젝트 배치하기(Layout 화면)

  • “Layout” 버튼을 눌러 Layout 화면으로 이동합니다.


  • Layout에는 Rect, Circle, Character, Text 같은 오브젝트 노드
    와 Button, Stick 같은 조작 노드를 배치합니다.


  • 오브젝트를 드래그해 옮기고, 네 모서리의 흰색 핸들로 크기를 바꾸고, 그 위의 둥근 핸들로 방향을 정합니다.
  • “NODE” 버튼을 누르면 NodeEditor로 돌아갑니다.

2-3. 프로그램 실행하기(Play 화면)

  • NodeEditor나 Layout 화면 오른쪽 위의 ▶(Play) 버튼으로 Play 화면으로 넘어가 프로그램이 실행됩니다.
  • Play 화면 오른쪽 위의 □ (Stop) 버튼을 길게 누르면 Play가 멈추고 편집 화면으로 돌아옵니다.
  • Play에서는 오브젝트 노드가 1/60초(1프레임)마다 그려지며 물리 연산과 함께 움직입니다.
  • 화면 터치, 화면 위의 JoyStick, 키보드, 마우스로 조작할 수 있습니다.


  • Play 화면에서는 중력도 표현할 수 있습니다.
    핀볼이나 마리오 같은 게임을 만들려면 Dynamics(물리 연산)를 켜세요.
    Setting 노드를 추가하고 그 Property에서 Dynamics를 켜면 프로그램 전체에 물리 연산이 적용됩니다.
    각 오브젝트 노드에도 저마다 Dynamics 설정이 있으므로 개별적으로 켜야 합니다.

3. 세 가지 화면

3-1. NodeEditor 사용법

노드를 배치하고 선으로 연결하는 화면입니다.


조작 결과
배경에서 한 손가락 드래그 화면 이동
두 손가락 핀치, 마우스 휠 화면 확대·축소
더블클릭 후 드래그(배경) 범위 선택(여러 노드 선택)
배경 길게 누르기 CREATE NEW NODE 열기
노드 드래그 노드 이동(여러 개 선택했다면 모두 함께)
노드 더블클릭 또는 길게 누르기 Property 열기(여러 개 선택했다면 다중 노드 메뉴)
단자 사이 드래그 선 연결(잘못 연결되지 않도록 터치 후 잠시 멈췄다가 드래그하세요)
선 길게 누르기 또는 밖으로 빼내기 연결 끊기
단자에서 바깥으로 드래그해 놓아도 끊을 수 있습니다

3-2. Layout 화면 사용법

오브젝트의 위치, 크기, 회전을 정하는 화면입니다. 회색 사각형이 Play할 때 보이는 범위입니다.


조작 방법은 기본적으로 NodeEditor와 같습니다.

조작 결과
한 손가락 드래그(배경) 화면 이동
마우스 휠 / 두 손가락 핀치 확대·축소
오브젝트 드래그 이동(여러 개 선택했다면 모두 함께)
오브젝트 탭 선택. 이 선택은 NodeEditor에서도 유지됩니다
핸들 드래그 크기 변경 / 회전
더블클릭 후 드래그(배경) 범위 선택
배경 길게 누르기 CREATE NODE 열기
선택한 것 길게 누르기 Property 열기(여러 오브젝트를 선택했다면 Duplicate/Delete 메뉴)
오브젝트를 선택하면 오른쪽에 “50” 같은 숫자가 표시됩니다.
이 숫자가 SortingLayer이며, 값이 클수록 앞쪽에, 작을수록 뒤쪽에 그려집니다.
아래의 ▲▼ 버튼으로 값을 조절할 수 있습니다.

그 밖에 SETTING 노드에 GridSnap 설정이 있습니다.
켜면 오브젝트가 10픽셀 단위로 움직입니다.

회색 영역의 크기는 Setting 노드에서 바꿉니다.

4. MENU

오른쪽 위의 MENU 버튼을 누른 채 손가락을 항목 방향으로 밀었다가 떼면 그 항목이 실행됩니다. 보통 버튼처럼 눌러도 됩니다.

오른쪽 위의 ▶ 버튼을 누르면 Play 화면으로 넘어가 프로그램이 실행됩니다.
Layout 을 누르면 Layout 화면으로 이동합니다.

4-1. 메뉴 항목

NEW NODE 새 노드를 추가하는 CREATE NODE를 엽니다. 배경을 길게 눌러도 같은 창이 열립니다.
SAVE 현재 프로그램에 이름을 붙여 저장합니다(4-2 참조).
LOAD 저장한 프로그램을 불러옵니다(4-3 참조).
UNDO 직전 조작을 취소합니다.
REDO 취소한 조작을 다시 실행합니다.
FIT 모든 노드가 화면에 들어오도록 확대율과 위치를 맞춥니다.
NEW 전부 지우고 새로 만듭니다.
SETTING 앱 자체의 설정을 엽니다(4-4 참조). SETTING 노드와는 다른 것입니다.
OPEN HELP 이 도움말 페이지를 엽니다.

Compo 안에서 편집할 때는 왼쪽 항목이 Compo용 항목으로 바뀝니다. 자세한 내용은 “Compo 노드” 장에서 설명합니다.

4-2. SAVE(저장)

이름을 붙여 이 기기에 저장합니다. 같은 이름이 이미 있으면 덮어씁니다. 이름에는 영문자, 숫자, 일부 기호를 쓸 수 있습니다.
AUTO에 체크하면 자동 저장이 켜져 이후 30초마다 자동으로 저장됩니다(Play 중에는 저장하지 않습니다).
EXPORT을 누르면 프로그램을 파일로 내보낼 수 있습니다. 백업하거나 남에게 건넬 때 편리합니다.
형식은 .ngz(gzip 압축)와 .json(텍스트) 중에서 고를 수 있습니다.
.ngz 파일의 확장자를 .gz로 바꾸기만 하면 일반 압축 해제 프로그램으로 JSON을 꺼낼 수 있습니다.

저장은 최대 256개까지 할 수 있습니다. 사용 중인 브라우저 안에 저장되므로 다른 기기나 브라우저에서는 보이지 않습니다.
저장 데이터는 nodegram 안에 들어 있으므로 스마트폰에서 nodegram 바로가기를 지우면 데이터도 함께 사라질 수 있습니다.
중요한 것은 EXPORT로 파일을 남겨 두는 편이 좋습니다.

4-3. LOAD(불러오기)

저장된 프로그램 목록이 표시됩니다. 이름 옆의 버튼으로 삭제할 수도 있습니다.
IMPORT를 누르면 EXPORT로 내보낸 파일을 불러올 수 있습니다. 불러오는 방식은 두 가지로, 불러오기는 현재 내용을 대체하고 추가로 불러오기는 현재 프로그램을 그대로 두고 그 아래에 파일을 이어 붙입니다.

3D 소프트웨어로 만든 .obj 파일을 IMPORT하면 3D 데이터가 POLYGON 노드로, 또는 LINE 노드(3D 표시)에 붙는 ARRAY 노드로 읽힙니다. 자세한 내용은 9-11. 3D 오브젝트를 참조하세요.

4-4. SETTING(앱 설정)

앱 자체의 설정입니다. 여기서 바꾼 내용은 프로그램에 저장되지 않고 이 기기에만 남습니다.
Wire：선의 모양(곡선／직선)을 고릅니다.
NodeColor：노드의 색을 고릅니다.
Language：표시 언어를 바꿉니다.
일본어, 영어, 중국어(간체), 프랑스어, 독일어, 힌디어, 인도네시아어, 이탈리아어, 한국어, 포르투갈어, 러시아어, 스페인어, 태국어, 튀르키예어, 베트남어

FPS나 Dynamics 같은 장면별 설정은 여기가 아니라 SETTING 노드에 있습니다. 이름이 비슷하니 헷갈리지 마세요.

5. 스마트폰과 PC에서


스마트폰에서
  • 터치 조작:
    한 손가락으로 밀고 두 손가락으로 확대합니다. 길게 누르기, 더블탭 후 드래그 등은 PC와 똑같이 동작합니다.

  • 화면 회전:
    기기의 방향에 따라 화면도 함께 회전합니다. Play 중에는 SETTING 노드에서 정한 방향(가로=Horizontal／세로=Vertical)이 적용되며, 반대로 들고 있으면 안내가 표시됩니다.
  • iOS 관련 안내: 
    iPhone 등 iOS 기기에서는 Safari 메뉴에서 아래의 ①, ②를 탭해 툴바를 숨기면 전체 화면에 가까워져 nodegram을 훨씬 편하게 쓸 수 있습니다.
    완전한 전체 화면을 원한다면 Safari의 공유 메뉴에서 “홈 화면에 추가”를 선택하세요. nodegram이 앱처럼 동작하므로 이 방법을 권장합니다.
    다만 홈 화면에서 그 아이콘을 지우면 저장 데이터도 사라질 수 있으니 주의하세요. 중요한 것은 기기의 폴더에 Export 해 두세요.

6. 노드 설명



In/Out은 입력 단자 수／출력 단자 수를 뜻합니다.

상수

노드 입력/출력 설명
Constant 0/1 Value에 설정한 숫자를 출력합니다.

계산

노드 In/Out 설명
＋ 2/1 입력① ＋ 입력②의 결과를 출력합니다.
덧셈 노드가 늘 필요한 것은 아닙니다. 입력 단자 하나에 여러 선을 연결하면 자동으로 더해지므로 입력①에 선 두 개를 연결하기만 해도 그 합을 얻을 수 있습니다.
－ 2/1 입력① － 입력②의 결과를 출력합니다
× 2/1 입력① × 입력②의 결과를 출력합니다
÷ 2/1 입력① ÷ 입력②의 결과를 출력합니다. 분모가 0이면 0을 출력합니다.
√ 1/1 입력①의 제곱근을 출력합니다. 입력이 0 이하면 0을 출력합니다.
Compare 2/1 입력①과 입력②를 비교합니다(=, >, <, ≠, ≥, ≤). 조건이 맞으면 1, 아니면 0을 출력합니다.
Not ( ! ) 1/1 입력①이 0이면 1을, 그렇지 않으면 0을 출력합니다.
Pos Angle 2/1 위치를 각도로. ArcTan2(입력②, 입력①)를 도 단위로 출력합니다.
Angle Pos 1/2 각도를 위치로. 도 단위의 각도에 대해 (cos, sin)을 출력합니다.
Random 1/1 0 이상 Number 미만의 정수 난수를 출력합니다. Play를 시작할 때와 입력①이 0이 아닌 프레임마다 새 값을 뽑습니다. Use Seed를 켜고 Seed 값을 지정하면 Play할 때마다 같은 순서가 반복됩니다.
Int 1/1 정수로 만듭니다. Round 속성에서 Floor / Round / Integer를 고를 수 있습니다.
기본값인 Floor는 입력보다 작거나 같은 가장 가까운 정수를 취해 2.8은 2, -0.1은 -1이 됩니다. Round는 가까운 쪽으로 반올림하고, Integer는 정수 부분만 남깁니다.

값과 시간

노드 In/Out 설명
WARP IN 1/0 오브젝트를 옮기는 장치의 “입구”입니다. 자식으로 지정한 오브젝트에 작용합니다. 입력이 0이 아니게 되면 그 자식은 같은 Index를 가진 WARP OUT의 위치와 각도로 이동하며, 입력이 0이 아닌 동안 그곳에 고정됩니다. 0으로 돌아오면 풀려나 다시 자유롭게 움직입니다. 속성은 Index뿐입니다. Compo 안에는 놓을 수 없습니다.
WARP OUT 0/0 워프의 “출구”입니다. 같은 Index를 가진 WARP IN이 보낸 오브젝트가 이 위치와 각도로 나타납니다. 속성은 Index뿐입니다. Layout 화면에서 옮기고 회전시킬 수 있습니다(크기가 없으므로 확대·축소는 되지 않습니다). 오브젝트를 부모로 두면 함께 움직입니다. Compo 안에는 놓을 수 없습니다.

IN 1/0 노드의 출력을 멀리까지 보내는 데 씁니다. IN 노드에 연결한 신호는 같은 인덱스를 가진 모든 OUT 노드에서 나옵니다. 같은 인덱스의 IN 노드를 두 개 만들 수는 없습니다. Compo 인덱스를 지정하면 그 Compo 안까지 닿습니다.
Compo 노드에 대해서는 7. Compo 노드를 참조하세요.
OUT 0/1 멀리서 보낸 값을 받는 데 씁니다. IN 노드에 들어간 값이 이곳, 즉 그 인덱스를 가진 모든 OUT 노드에서 나옵니다. 같은 인덱스의 OUT 노드는 여러 개 만들 수 있습니다. Compo 인덱스를 지정하면 그 Compo 안까지 닿습니다.
Compo 노드에 대해서는 7. Compo 노드를 참조하세요.

장면 설정

노드 In/Out 설명
MEMO 0/0 작업 화면에 적어 두는 메모입니다. Play 중에는 그려지지 않습니다.
BG 0/0 Play 화면의 배경입니다. 장면마다 하나이며 언제나 가장 뒤에 있습니다.
TEXTURE 노드를 지정하면 그 그림이 배경 전체에 타일처럼 깔립니다. TEXTURE가 없으면 Color의 단색으로 채워집니다.
SETTING 0/0 장면 전체의 설정입니다.
스마트폰 화면 방향(ScreenOrient), Play 영역 크기(ScreenSize, ScreenLong, ScreenShort), FPS, Dynamics(Gravity, Friction%, Bounce%, Drag%), Play 정지 버튼 색(StopBtnCol), GridSnap을 바꿀 수 있습니다. 장면마다 하나만 만들 수 있습니다.
장면에 3D 관련 노드가 있으면 시점의 높이와 화면까지의 거리를 정하는 속성도 나타납니다.

7. Compo 노드

  • 여러 노드를 하나의 노드처럼 다룰 수 있게 해 주는 특별한 노드입니다.

    같은 노드 조합이 프로그램 안에 열 번 나온다고 해 봅시다. 한 번만 만들어 두고 다시 쓰고 싶어집니다.
    nodegram에서는 여러 노드를 하나의 Compo 노드로 묶고 그 Compo를 복제해서 씁니다.

    같은 적을 열 개 만들려면 먼저 하나의 프로그램을 만들고, 그 노드들을 Compo로 묶고, Compo를 복제해 Layout에 배치하세요.

    복제한 Compo 노드는 프로그램으로서는 같은 것이라 하나를 고치면 나머지도 바뀝니다. 다만 좌표, 변수, 수명 등은 실행 중에 Compo마다 따로 움직입니다.

  • Compo 노드를 만드는 순서
  1. 묶고 싶은 노드들을 선택합니다.
    여러 개를 한꺼번에 고르려면 더블클릭한 뒤 드래그하세요.
    더블클릭의 두 번째 클릭에서 마우스를 떼지 말고 그대로 드래그해 범위를 감쌉니다.
    스마트폰에서는 “톡, 톡 누른 채, 쓱” 하는 느낌입니다.
    (이 예에서는 왼쪽이 플레이어 기체이고, 네모로 감싼 부분이 다가오는 적 기체 하나의 프로그램입니다.)



  2. 노드를 여러 개 선택한 상태에서 그중 하나를 길게 누르면 메뉴가 나옵니다. “MAKE COMPO”를 고르고 확인 창에서 “Yes”를 누르세요.




  3. 여러 노드가 “C1”이라는 하나의 Compo 노드가 되었습니다.


  4. C1 노드를 길게 누르거나 더블클릭하면 Compo 안의 NodeEditor가 열립니다.
    Compo에 연결되어 있던 선은 “C1 1”, “C1 2”라는 OUT 노드가 되어 있습니다.

    오른쪽의 “MENU”를 누르면 왼쪽 줄이 Compo 관련 명령으로 바뀝니다.
    “Duplicate”를 누르면 이 Compo 노드가 복제됩니다.
    오른쪽 아래의 “PARENT”를 누르면 이 NodeEditor를 나와 위쪽 NodeEditor로 돌아갑니다.



  5. 위쪽 NodeEditor를 보면 Compo 노드가 여러 개 생긴 것을 알 수 있습니다.
    “C1 (2)”에도 같은 입력을 주어야 하므로 입출력을 똑같이 연결하세요.



  6. “LAYOUT”을 눌러 각 Compo의 위치를 정합니다.


  7. Play “▶”를 누르면 적 기체가 여러 대 나오고 저마다 따로 움직입니다.

  8. 많이 복제하려면 Compo 노드들을 함께 선택한 뒤 그중 하나를 길게 눌러 “Duplicate”하세요.
    그리고 모든 Compo 노드에 같은 값을 주고 싶다면 IN 노드와 OUT 노드가 편리합니다.


  • Compo 노드와 인스턴스

    두 Compo 노드의 내용이 같아서 한쪽을 고치면 다른 쪽도 바뀔 때 “두 노드는 인스턴스 관계”라고 하며, 복제해서 만드는 것을 “Compo 노드의 인스턴스를 만든다”고 합니다.
    같은 Compo 번호를 가진 Compo 노드는 인스턴스 관계이며 하나의 프로그램을 함께 씁니다.
    (참고로 인스턴스 관계를 끊는 것을 Unique라고 하며 Compo의 플릭 메뉴에 있습니다. 아래 참조)

    C 뒤의 숫자가 같으면 인스턴스 관계인 같은 Compo입니다.
    “C1 (1)”과 “C1 (2)”는 인스턴스 관계입니다.
    “C1 (1)”과 “C2 (1)”은 다른 Compo이며 인스턴스 관계가 아닙니다.
    ( ) 안의 숫자는 같은 Compo의 복제본을 구별하기 위한 것입니다.

    Compo끼리 인스턴스 관계라도 Play 중에는 Compo마다 매개변수가 따로 다뤄집니다.
    캐릭터의 등장과 소멸, 좌표, 그리고 노드 안의 count, var, array 등은 각각 자기 값을 지닙니다.

  • Compo 노드 안의 MENU


    Duplicate, Delete：Compo 노드의 복제와 삭제입니다.

    Unique    ：이 Compo 노드의 인스턴스 관계를 끊는 항목입니다. 어떤 Compo의 내용을 가져와 다른 적을 만들고 싶을 때 씁니다. Compo 번호가 새 번호로 바뀝니다.

    Expand    ：편집 중인 Compo 안의 노드를 메인 NodeEditor로 되돌리고 그 Compo 자체는 사라집니다. Make Compo의 반대입니다. 인스턴스 관계인 Compo는 함께 Expand되지 않습니다.

  • Compo 노드와 IN, OUT 노드

    Compo 노드에는 입력 단자와 출력 단자가 두 개씩뿐이지만 IN 노드와 OUT 노드로 입력을 늘릴 수 있습니다.
    IN, OUT 노드의 속성에는 Compo 번호를 지정할 수 있어 특정 Compo에 값을 보낼 수 있습니다.


    Compo 안에서는 Compo 번호가 없는 IN 노드를 쓸 수 있습니다.
    Compo 안에서는 Compo 번호가 없는 OUT 노드를 쓸 수 없습니다(같은 OUT 노드를 여러 개 만들 수 없기 때문입니다).

    주의하세요. Compo 번호가 붙은 IN, OUT 노드는 똑같이 생겼어도 Compo 안에 있느냐 밖에 있느냐에 따라 뜻이 완전히 달라집니다.
    위 그림의 “IN 노드(파랑): C1 인덱스2”는 Compo 안에도 밖에도 있지만 둘은 같은 것이 아닙니다. 안쪽 것은 Compo의 출력②에 이어지고, 바깥쪽 것은 Compo의 입력②에 이어져 안쪽의 “OUT 노드: C1 인덱스2”로 값을 전합니다.

  • Compo의 Enable 입력과 Enable 출력

    Compo 노드를 캐릭터로 쓸 때는 Enable 입출력으로 그 캐릭터가 나타나고 사라지는 것을 조절할 수 있습니다.

    Enable 출력은 캐릭터가 있는 동안 1이고 파괴되면 0이 됩니다.

    Enable 입력이 0에서 1(0이 아닌 값)로 바뀌면 Compo 안의 프로그램이 시작되고 캐릭터가 활성화됩니다. 캐릭터를 유지하려면 0이 아닌 값을 계속 주어야 하며, 입력이 0이 되거나 캐릭터가 파괴되면 사라집니다.
    Enable 입력에 아무것도 연결하지 않으면 1을 계속 주는 것과 같습니다.

    이미 사라진 캐릭터라도 입력이 다시 0에서 다른 값으로 바뀌면 처음 상태부터 다시 시작합니다.
    아래는 캐릭터가 파괴된 뒤 3초 후에 처음 위치에 다시 나타나게 하는 프로그램입니다.


  • Compo 노드 안의 부모는 하나만

    Compo 안에서 오브젝트의 부모-자식 관계에 가장 위의 부모 오브젝트 노드가 둘 이상 있으면 안 됩니다. 하나의 Compo 노드로 캐릭터 둘을 만드는 것은 상정하지 않았습니다.
    부모가 둘이라도 그 둘에게 공통의 부모가 지정되어 있다면 문제없습니다.
    오브젝트 노드가 하나도 없는(부모가 없는) 경우도 괜찮습니다.


  • Compo 안에 만들 수 없는 노드

    BG, Setting, Stick, Button, Screen, OnBreak는 Compo 안에 만들 수 없습니다.

예)

9. 사양

9-1. 2D 전용

nodegram은 2D 전용입니다. 좌표는 X(오른쪽이 ＋)와 Y(위쪽이 ＋) 두 축입니다. Setting 노드에서 Dynamics를 켜면 캐릭터가 화면 아래쪽으로 떨어집니다.
위에서 내려다보는 게임을 만들 때는 SETTING 노드에서 Dynamics를 끄거나 전체 중력을 0으로 하세요.

9-2. FPS

목표 프레임 레이트는 SETTING 노드에서 60 또는 30을 고릅니다(기본값 60). 노드 계산도 물리 연산도 이 FPS에 맞춰 진행됩니다. 처리가 무거워지면 Play가 느려져 실제 프레임 레이트가 설정값보다 떨어집니다.

9-3. Dynamics(물리 거동)

Rect, Circle, Character, Shot 같은 오브젝트에는 물리 모드(Dynamics)를 지정할 수 있습니다. 거동은 Unity의 Rigidbody2D와 거의 같습니다.

모드 거동
Off 물리 없음. 노드 입력(X,Y)이 좌표를 그대로 옮깁니다.
Static 움직이지 않는 벽이나 바닥입니다. 중력이나 충돌로 움직이지 않습니다.
Dynamic 중력과 충돌로 물리적으로 움직입니다. 노드의 X/Y 입력은 “힘”으로 작용합니다.
Kinematic 중력과 충돌로는 움직이지 않지만 노드 입력으로는 움직일 수 있으며, Dynamic 오브젝트와 부딪혀 밀어낼 수도 있습니다.

밀도 설정은 없으며 대체로 평범한 나무 정도로 다룹니다.

9-4. SortingLayer(표시 순서)

각 오브젝트의 SortingLayer(0〜100, 기본값 50)가 Play 화면에서의 겹침 순서를 정합니다. 숫자가 클수록 앞쪽(위)에 그려집니다. BG(배경)는 언제나 가장 뒤입니다.
값이 같으면 추가한 순서대로 표시됩니다.

9-5. 좌표

  • 좌표는 X(오른쪽이 ＋)와 Y(위쪽이 ＋)입니다. Layout의 한가운데가 원점(0,0)입니다.
  • 각도는 도 단위이며 반시계 방향이 ＋입니다. 0°＝오른쪽(X＋), 90°＝위(Y＋), 180°＝왼쪽(X−), 270°＝아래(Y−)입니다. ANGLE POS / POS ANGLE / GetRot / ROTATE / 오브젝트의 Angle 속성이 모두 이 기준을 따릅니다.
  • 오브젝트의 Property에 있는 Coord 속성으로 노드 입력 X/Y의 뜻이 달라집니다.
    • WORLD：입력값이 절대 좌표로 작용합니다(부모가 있으면 그에 대한 상대 좌표).
    • LOCAL：입력값이 처음 배치한 곳으로부터의 차이로 작용합니다. 부모가 지정되어 있으면 부모로부터의 차이도 함께 적용됩니다(Parent 좌표).
  • 3D 오브젝트의 좌표는 9-11. 3D 오브젝트를 참조하세요.

9-6. 해상도

Play할 때 보이는 범위는 Layout의 회색 사각형만큼입니다.
화면 방향(가로=Horizontal／세로=Vertical)은 Setting 메뉴가 아니라 SETTING 노드에서 바꾸며, 실제 화면 크기에 맞춰 표시됩니다.
해상도를 고정하고 싶다면 Setting 노드의 ScreenSize를 쓰세요.

9-7. Tag

Tag는 그룹입니다.
예를 들어 작은 적 모두에게 “Enemy_tiny” Tag를 붙이거나, 부술 수 있는 배경과 고정 배경을 “bg_destroyed”, “bg”로 구분할 수 있습니다.
Shot, OnBreak, Rect, Circle, Character 같은 노드가 Tag를 씁니다.


9-8. 노드 다루기


  • 노드 하나의 입력에는 선을 여러 개 연결할 수 있습니다. 입력이 여럿이면 그 합이 노드에 전해집니다. 그림에서는 맨 위 단자에 10+20→30이 들어갑니다.

  • 노드끼리의 부모-자식 연결(위쪽 단자에서 아래쪽 단자로)은 오브젝트를 함께 움직이는(Transform) 것 말고도 “관계”를 나타내는 데 쓰입니다.
    예를 들어 Texture 노드와 오브젝트 노드, OnBreak 노드와 감시할 오브젝트, Array 노드와 Line 노드가 그렇습니다.
    보통 부모 하나에 자식은 여럿일 수 있지만 자식 하나에 부모는 하나뿐입니다.
    Texture 노드, OnBreak 노드, Array 노드는 예외로 각각 부모를 여러 개 가질 수 있습니다.


9-9. 1프레임 안의 처리

모든 노드가 동시에 처리됩니다.
어느 노드를 먼저 만들었는지에 따라 결과가 달라지지 않습니다.

오브젝트 노드 등은 1프레임에 한 번 처리됩니다.
Counter, Var, Trigger, Random, Array처럼 “값을 기억하는 노드”도 1프레임에 한 번만 갱신됩니다.
＋나 × 같은 계산 노드는 값을 기억하지 않으므로 값이 필요할 때 계산됩니다.
계산 노드가 고리를 이루더라도 한 노드는 1프레임에 한 번만 처리됩니다.

9-10. UNDO / REDO

MENU의 UNDO / REDO로 노드의 생성, 삭제, 이동, 연결, Property 변경 등을 취소하거나 다시 실행할 수 있습니다. 50단계까지 되돌릴 수 있습니다.

TEXTURE / LINE / SEQUENCER 각 에디터는 저마다 따로 UNDO 이력을 가집니다. 에디터 안의 ◁ / ▷ 버튼을 쓰세요. LINE Editor와 SEQUENCER도 50단계까지 되돌아가며, TEXTURE는 크기에 따라 횟수가 달라집니다.

참고로 Play 실행은 취소할 수 없고 저장과 불러오기도 취소할 수 없습니다.

9-11. 3D 오브젝트


nodegram에서 3D 오브젝트를 표시하는 방법은 Polygon과 ARRAY＋LINE(3D 표시용) 두 가지입니다. 둘 다 .obj 파일을 IMPORT할 때만 만들어집니다(CREATE NEW NODE로는 만들 수 없습니다).

다만 nodegram 자체는 어디까지나 2D 무대입니다. 3D 오브젝트는 3D처럼 보이는 그림을 2D 소재로 쓰기 위한 것일 뿐이며, 다른 2D 오브젝트와 마찬가지로 표시 순서는 Sorting Layer 설정으로 정해집니다. 같은 Sorting Layer의 Polygon 노드는 하나의 3D 장면처럼 함께 처리되므로 깊이의 앞뒤도 제대로 표현됩니다.

3D 오브젝트에는 Z 좌표가 있습니다. 화면의 위치가 z=0이고 안쪽이 +z, 보는 쪽이 -z입니다. 시점에서 화면까지의 거리와 시점의 높이는 setting 노드에서 바꿀 수 있습니다.
2D 오브젝트와 부모-자식 관계를 맺을 수도 있지만 그때는 z=0에서 작업하는 것이 좋습니다.

LINE(3D 표시)으로 만들려면 LINE 노드의 자식인 ARRAY의 값을 x,y,z 세 개씩의 연속으로 넣으세요. 구분자(9999,9999,9999)까지가 하나로 이어진 선이 되고 그 뒤는 새로운 선이 됩니다(형식: x,y,z, x,y,z, ,,, 9999,9999,9999, x,y,z, ,,,, 9999,9999,9999). ARRAY의 부모로 LINE을 여러 개 지정할 수도 있습니다.

10. 알아두면 좋은 것

  • 스마트폰에서 쓸 때：
    nodegram 바로가기를 홈 화면에 추가하면 앱처럼 쓸 수 있습니다. 다만 앱과 마찬가지로 그것을 지우면(홈 화면의 바로가기를 지우면) 저장 데이터도 함께 사라질 가능성이 높습니다. 완성한 프로그램은 Export로 따로 파일에 남겨 두세요.

    일부 스마트폰 브라우저에서는 표시나 터치 위치가 어긋날 수 있습니다.
    그럴 때는 nodegram을 종료하고 태스크를 지운 뒤(앱을 지우는 것과는 다릅니다) 기기를 가로 방향으로 반듯하게 들고 다시 실행하면 나아집니다.
  • 자동 저장:
    save 화면에서 “auto save”가 켜져 있으면 1분마다 직전 파일에 덮어씁니다. 따로 남기고 싶다면 Save로 새 이름을 붙이세요.

  • 권리: 
    nodegram으로 만든 작품의 권리는 모두 만든 사람의 것입니다. 저희가 마음대로 쓰거나 권리를 주장하지 않습니다.
    nodegram의 코드와 사양에 대한 권리는 저(harada)에게 있습니다. nodegram의 코드를 허락 없이 재배포하지 말아 주세요.

  • 저작권과 문제: 
    저작권이 있는 것을 가볍게 쓰지 말아 주세요.
    또한 nodegram을 써서 생긴 문제에 대해서는 책임을 지지 못합니다(물론 문제를 일으키는 코드를 일부러 넣는 일은 없습니다).
