1. What is nodegram?

nodegram is a tool for programming with nodes.

Connect a stick node to a character node and the character already moves.



• Program on a phone or a PC.

• Let other people play the games you make.
• nodegram runs on the web, so you can program anywhere you have a connection (a nodegram program is only about the size of a single image).

What is node programming?
nodegram gives you more than 40 kinds of nodes — a node that only adds, a node that remembers a number, a node that checks whether a key is held down, and so on.
Node programming is a team of workers (Nodes) passing information to each other to get a big job done. Every worker takes the value handed to it by the previous worker, does its own small job, and passes the result on. All of them are working all the time.
Text-based programming works differently: a single worker reads the instructions one by one and carries them out in order.

2. Getting started


How to build a shooting game (2 min)

nodegram has three views:
Program your nodes in NodeEditor
Place your objects in Layout
Run your program in Play 

.

2-1. Creating nodes (NodeEditor)

  • In the NodeEditor, press and hold the background (the empty black area) to open the “CREATE NEW NODE” dialog.


  • Pick a node from the list and it appears in the NodeEditor.
  • Press and hold a node — or double-click it — to open its Property dialog, where you set that node up in detail.
    This is where you change things like an object’s colour.
    There is no OK button: every change takes effect immediately. Close the dialog with the × at the top right, or by tapping outside it.
    DUPLICATE copies the node and DELETE removes it.
  • Drag a node (touch and move) to reposition it.
  • Drag from the output port on the right of a node to an input port (on the left of another node) to connect a wire. While the program runs, values then flow along that wire from the red port to the blue port.



  • Nodes with a port on top (a child port) can be connected from that child port to a parent port (underneath another node). The two then form a parent–child pair, and the child moves with the parent.
    For a player that fires bullets, for example, make the muzzle the child and the player the parent.

2-2. Placing objects (Layout)

  • Press the “Layout” button to switch to the Layout view.


  • In Layout you place object nodes such as Rect, Circle, Character and Text,
    and control nodes such as Button and Stick.


  • Drag an object to move it, use the white handles at its four corners to resize it, and the round handle above it to rotate it.
  • Press “NODE” to go back to the NodeEditor.

2-3. Running your program (Play)

  • The ▶ (Play) button at the top right of the NodeEditor or Layout view switches to Play and runs your program.
  • Press and hold the □ (Stop) button at the top right of the Play view to stop and return to editing.
  • In Play, object nodes are drawn every 1/60 second (one frame) and move together with the physics simulation.
  • Players can control them by touching the screen, or with the on-screen joystick, a keyboard or a mouse.


  • You can also use gravity in the Play view.
    For a pinball or Mario-style game, turn Dynamics (physics) on.
    Add a Setting node and turn on Dynamics in its Property to enable physics for the whole program.
    Each object node has its own Dynamics setting as well, so turn those on individually too.

4. MENU

Press and hold the MENU button at the top right, slide your finger towards an item and release to run it. It also works as a plain button.

The ▶ button at the top right switches to Play and runs your program.
Layout switches to the Layout view.

4-1. Menu items

NEW NODE Opens CREATE NODE so you can add a node. Pressing and holding the background does the same.
SAVE Saves the current program under a name (see 4-2).
LOAD Loads a saved program (see 4-3).
UNDO Undoes the last action.
REDO Redoes an undone action.
FIT Adjusts the zoom and position so that every node fits on screen.
NEW Clears everything and starts a new program.
SETTING Opens the settings for the app itself (see 4-4). This is not the same as the SETTING node.
OPEN HELP Opens this help page.

While you are editing inside a Compo, the items on the left change to Compo-specific ones. Those are covered in the “Compo nodes” chapter.

4-2. SAVE

Saves the program on this device under a name you choose. Saving under an existing name overwrites it. Names may use single-byte letters, digits and a few symbols.
AUTO to turn on auto-save, which then saves every 30 seconds (never while Play is running).
EXPORT writes the program out as a file — useful for backups and for handing your work to someone else.
You can export as .ngz (gzip compressed) or .json (plain text).
Just rename a .ngz file to .gz and any ordinary unzip tool can extract the JSON inside.

You can keep up to 256 saves. They live inside the browser you are using, so they are not visible from another device or another browser.
Saves are stored inside nodegram itself, so deleting the nodegram shortcut from your phone may delete them too.
For anything important, use EXPORT and keep a file.

4-3. LOAD

Shows the list of saved programs. The button next to each name deletes it.
IMPORT loads a file you exported earlier. There are two ways to load it: Load replaces what you have now, while Add keeps the current program and appends the file below it.

Importing an .obj file made in 3D software brings the model in as a POLYGON node, or as an ARRAY node to feed a LINE node (3D view). See 9-11. 3D objects for details.

4-4. SETTING (app settings)

Settings for the app itself. These are not stored in your program; they stay on this device only.
Wire: choose the wire shape (curved or straight).
NodeColor: choose the node colour scheme.
Language: change the interface language.
Japanese, English, Chinese (Simplified), French, German, Hindi, Indonesian, Italian, Korean, Portuguese, Russian, Spanish, Thai, Turkish and Vietnamese.

Per-scene settings such as FPS and Dynamics are not here — they live on the SETTING node. The names are similar, so take care not to mix them up.

5. On phones and PCs


On phones
  • Touch controls:
    Pan with one finger, pinch-zoom with two. Press and hold, double-tap then drag, and the rest work just as they do on a PC.

  • Rotating the screen:
    The view follows the device orientation. During Play the orientation set on the SETTING node (Horizontal or Vertical) is used, and a message appears if the device is held the other way.
  • A note for iOS: 
    On iPhone and other iOS devices, open the Safari menu and tap ① then ② to hide the toolbar. That gets you close to a full-screen view and makes nodegram much easier to use.
    For a truly full-screen experience, open the Safari share menu and choose “Add to Home Screen”. nodegram then behaves like an app, which we recommend.
    Be aware that deleting that home-screen icon may delete your saved data. Export anything important to a folder on your phone.

6. Node reference



In/Out is the number of input ports / output ports.

Constants

Node In/Out Description
Constant 0/1 Outputs the number set in Value.

Arithmetic

Node In/Out Description
＋ 2/1 Outputs Input 1 + Input 2.
You do not always need an add node: every input port accepts several wires and sums them, so two wires into Input 1 already give you their total.
－ 2/1 Outputs Input 1 − Input 2
× 2/1 Outputs Input 1 × Input 2
÷ 2/1 Outputs Input 1 ÷ Input 2. Returns 0 if the divisor is 0.
√ 1/1 Outputs the square root of Input 1. Returns 0 when the input is 0 or less.
Compare 2/1 Compares Input 1 with Input 2 (=, >, <, ≠, ≥, ≤). Outputs 1 when the comparison holds and 0 when it does not.
Not ( ! ) 1/1 Outputs 1 when Input 1 is 0, and 0 otherwise.
Pos Angle 2/1 Position to angle. Outputs ArcTan2(Input 2, Input 1) in degrees.
Angle Pos 1/2 Angle to position. Outputs (cos, sin) for an angle in degrees.
Random 1/1 Outputs a random integer from 0 up to (but not including) Number. It picks a new value when Play starts and on every frame where Input 1 is not 0. Turn on Use Seed and set a Seed value to get the same sequence every time you press Play.
Int 1/1 Converts to a whole number. The Round property offers Floor, Round and Integer.
Floor (the default) takes the nearest whole number at or below the input, so 2.8 becomes 2 and −0.1 becomes −1. Round rounds to nearest, and Integer keeps just the integer part.

Values and timing

Node In/Out Description
Trigger 1/1 Outputs 1 for a single frame at the moment the input changes from 0 to something other than 0.
DELAY(F) delays that 1 by the given number of frames.
Counter 2/1 A counter. Adds Input 1 every frame and subtracts Input 2, and outputs the number it is holding.
Type = Clamp keeps it between Min and Max; Loop wraps around within that range. Value (the starting number), Min and Max are all configurable.
Var 2/1 Works as a variable: it holds a single number and outputs it.
When the set signal on Input 2 is anything other than 0, it stores Input 1.
A starting value can be set.
Array 3/1 Works as an array.
Give it an index on Input 2 (the position in the array, starting at 0) and it outputs that element. Indices start at 0, so an array of length 3 uses 0, 1 or 2; anything below 0 or 3 and above returns 0.
A set signal on Input 3 overwrites the element at index (Input 2) with the value on Input 1.
Write the starting values separated by commas or line breaks.
Arrays pair up with the Sound node to act as sheet music, and with the Line node to draw a polyline. The SEQUENCER and LINE buttons in the Property dialog open editors for exactly those two uses (see below).
An array is also where a 3D wireframe is stored (see 9-11. 3D objects).
GetPos 0/2 Reads the parent object’s current X and Y position. Switchable between WORLD and LOCAL.
GetRot 0/1 Outputs the parent object’s current angle, counter-clockwise positive. Switchable between WORLD and LOCAL.
Velocity 0/2 Outputs the parent object’s X and Y speed per second (Y is positive upwards). A larger Frames value averages over more frames, giving a smoother reading.

The ARRAY editors (SEQUENCER / LINE)


  • LINE editor:
    A tool for drawing the polyline you feed to a Line node.
    The origin is at the centre of the editing area, X is positive to the right and Y positive upwards, both from −99 to 99.
    DRAW draws the polyline. While you are drawing, the DRAW button becomes Endpoint; press it to finish the current stroke.
    MOVE moves a vertex, ERASE deletes a single segment, VIEW pans the view, and ◁ ▷ undo and redo. When you close the editor the drawing becomes a list of x,y numbers, where x,y = (9999,9999) breaks the line.
    Set a LINE node as the ARRAY’s parent and that LINE draws whatever the array holds. One ARRAY can have several parents (several LINE nodes).


  • SEQUENCER editor:
    A tool for building the array of notes you feed to a Sound node. Eighth notes only, 8 per bar, up to 500 bars, three octaves.
    Click or drag in DRAW mode to place notes, and drag in ERASE mode to remove them.
    When you close the editor you get an array of eighth notes where C is 0 and D is 1. A rest is 99 (in fact any value above 80 counts as a rest), and the bar containing the last note is padded with rests to its end. Semitones are written as 0.5.
    Tick the Chromatic box and each cell becomes one of the 12 semitones (C=0, C♯=1, D=2, D♯=3, E=4, F=5, F♯=6, G=7, G♯=8, A=9, A♯=10, B=11), so an octave spans 12. The Sound node has the same checkbox — keep the two set the same way.


  • An array on its own makes no sound; you need a program like the one linked below.

Output and objects

Node In/Out Description
Text 2/0 Displays text. With nothing connected it shows the text set in the Text property; with a wire connected it shows that number. Input 2 turns the display on and off. Numbers are rounded at the sixth decimal place and shown to five. Text colour, layout and the surrounding box can all be configured.
Rect 3/0 A rectangle. With Dynamics off, Inputs 1 and 2 are the x and y position; with Dynamics on they are an external force. Input 3 turns the object on and off. Colour, border, Tag, size, rotation, Sorting Layer and more are configurable. Broken by 1–3 lists the My Tag values of the objects that are able to destroy this one.
For Dynamics and Tag, see 9. Specifications.
Circle 3/0 A circle. Apart from its shape and the Radius property, its inputs and properties match RECT.
Character 3/0 A character that can walk and jump. Inputs 1 and 2 are the movement speed; Input 3 jumps at the moment it changes from 0 or less to a positive value.
Jump height is proportional to the input value and only works while the character is on the ground. For physics and jumping, turn Dynamics on in both SETTING and the Character. For a top-down game, leave Dynamics on and set Gravity to 0. Flip mirrors the texture to match the facing direction, AutoRot turns the character to face the way it is moving, and KeepOnScr keeps it inside the screen.
It has a child port, but it cannot be made the child of an object. The only node you can set as its parent is WARP IN.
Shot 1/1 Input 1 fires a bullet. Bullet Count is how many bullets can exist at once. My Tag destroys anything whose Broken by matches it, while the SHOT node’s own Broken by 1–3 lists what makes its bullets disappear, by node type or Tag. The output is 1 only on the frames where a shot was actually fired. Keep Off-Screen keeps bullets alive outside the screen, and once the bullet limit is reached the oldest bullets are removed.
Line 5/0 Draws a line from (X1,Y1) to (X2,Y2). When Input 5 (SET) is connected, the shape updates whenever that input is not 0 and holds its previous shape while it is 0. With nothing connected it updates every frame.
Give it an ARRAY child and Inputs 1–4 are ignored: the array is read as x1,y1,x2,y2,… and drawn as one continuous polyline. x=9999, y=9999 breaks the line. Coord switches between WORLD and LOCAL.
If the child ARRAY holds 3D data (x,y,z triples) it is automatically drawn as a 3D LINE. See 9-11. 3D objects for details.
Sound 3/0 Input 1 is the pitch (C=0, D=1, …), Input 2 the volume and Input 3 the play signal. With Inputs 1 and 2 unconnected, the Tone and Volume properties are used instead. A sustained sound keeps playing while the signal is not 0, while decaying sounds and effects play once on the rising edge or when the pitch changes. Any pitch above 80 (such as 99) is a rest. The Tone property moves in steps of 0.5 (a semitone), but Input 1 accepts any decimal value.
Turn Chromatic on and Tone becomes a 12-semitone number (0=C, 1=C♯, 2=D…). With it off you get a 7-note scale where 0.5 is a black key. When feeding an array in as pitch, match this setting to the Chromatic setting in that array’s SEQUENCER — if they differ the pitches will be wrong.
Polygon 7/0 An object that draws the faces (polygons) of a 3D model. It cannot be created from CREATE NEW NODE; it appears only when you IMPORT an .obj file.
Its inputs are a 3D position, a 3D rotation and a scale.
See 9-11. 3D objects for details.

Controls

Node In/Out Description
Stick 1/2 An on-screen joystick. Output 1 is the stick’s horizontal tilt and Output 2 its vertical tilt. It can be analogue or digital, and can be mapped to a keyboard or a gamepad.
Button 1/1 An on-screen button. Outputs 1 while it is held. It can be mapped to a keyboard or a gamepad.
Keyboard 0/1 Outputs 1 while the chosen key is held down.
Touch 0/3 Screen touch. Output 1 is the touch X and Output 2 the touch Y (the centre is 0,0); Output 3 is 1 while the screen is being touched.

Other nodes

Node In/Out Description
TEXTURE 1/0 Holds a piece of pixel art you draw, and paints it onto the object you set as its parent. It can be assigned to Rect, Circle, Chara, Shot and BG, and it can have several parents (several object nodes).
An input of 0 hides it. Connect several textures to one object and make just one of them Visible to switch between them.
You can choose whether the picture is fitted to the object or tiled across it.
With no parent set, the texture can also be displayed on its own as a flat image.
When you need the same picture many times — for background tiles, say — one texture can be assigned to many objects.
For the texture editor itself, see “The TEXTURE editor”.
SENSOR 0/1 Outputs how many objects overlap the sensor area (the region you set in the Layout view). An object counts if it matches the Target condition or any of Tags 1–3, and each object is counted only once even when it matches several of them. Target=SCREEN instead returns 0 or 1 depending on whether the sensor area overlaps the visible screen. Give it a parent and the sensor follows that parent, which is itself excluded from detection.
ONBREAK 1/1 Outputs how many of its parent objects, or objects with the chosen Tag, were destroyed during the current frame. Several parent objects can be set.
With nothing to watch, an Onbreak node still works as an effect node: it also plays an effect at its own position when Input 1 changes from 0 to anything else. The effect type (NONE, PARTICLE, LINE, CIRCLE, BOX) and its colour are configurable.
ROTATE 1/0 A hinge for rotating a parent–child group. An object with ROTATE as its parent takes on that node’s position and rotation. Input 1 is the rotation offset from the angle set in Layout, positive values turning counter-clockwise.
SCREEN 3/2 Controls the camera during Play. X/Y are the camera position (an offset from the parent when it has one; Y is positive upwards) and S is the zoom, with a minimum of 0.05. An object with SCREEN as its parent becomes a fixed HUD that the camera does not affect.
Set the player object as SCREEN’s parent and the view follows the player.
RESTART 1/1 When the input changes from 0 to anything else, the whole program returns to the state it had when Play began. Positions, variables, counters, arrays, bullets and so on are all reset. The value that triggered the restart is kept on the output afterwards, which makes it handy for carrying lives or a score across a restart.
COMPO 3/3 A part that bundles several nodes into one. E enables and disables it; 1 and 2 exchange values with the inside.
For details see 7. Compo nodes.

    DrawDraws single dots in the selected colour. Drag to draw continuously.
    PaintFills a connected area of the same colour.
    PickPicks up a colour from the picture and makes it the current colour.

Warp

Node In/Out Description
WARP IN 1/0 The “entrance” of a teleport. It acts on the object set as its child. While the input is anything other than 0, that child jumps to the position and angle of the WARP OUT with the same Index and stays pinned there; when the input returns to 0 it is released and moves freely again. Index is its only property. It cannot be placed inside a Compo.
WARP OUT 0/0 The “exit” of a teleport. Objects sent by a WARP IN with the same Index appear at this position and angle. Index is its only property. In the Layout view it can be moved and rotated (it has no size, so it cannot be resized). Give it a parent object and it travels with it. It cannot be placed inside a Compo.

Signals

Node In/Out Description
IN 1/0 Sends a value to a distant part of the program. Whatever you connect to an IN node comes out of every OUT node with the same index. You cannot create two IN nodes with the same index. Give it a Compo index and it also reaches inside that Compo.
For Compo nodes see 7. Compo nodes.
OUT 0/1 Receives a value sent from elsewhere. Whatever goes into an IN node comes out here, at every OUT node sharing that index — several OUT nodes with the same index are allowed. Give it a Compo index and it also reaches inside that Compo.
For Compo nodes see 7. Compo nodes.

Scene settings

Node In/Out Description
MEMO 0/0 A note you write on the canvas for yourself. It is not drawn during Play.
BG 0/0 The background of the Play view. One per scene, always furthest back.
Assign a TEXTURE node and the picture is tiled across the background. With no texture assigned, the background is filled with the single Color.
SETTING 0/0 Settings for the whole scene.
Screen orientation on phones (ScreenOrient), the Play area size (ScreenSize, ScreenLong, ScreenShort), FPS, Dynamics (Gravity, Friction%, Bounce%, Drag%), the Play stop-button colour (StopBtnCol) and GridSnap. Only one per scene.
When the scene contains 3D nodes, extra properties appear for the height of the viewpoint and its distance from the screen.

7. Compo nodes

  • A special node that lets you treat a group of nodes as if it were a single node.

    Suppose the same combination of nodes shows up ten times in your program — you would want to build it once and reuse it.
    In nodegram you can bundle several nodes into one Compo node and then duplicate that Compo.

    To make ten copies of the same enemy, build one of them, bundle its nodes into a Compo, duplicate the Compo and place the copies in Layout.

    Duplicated Compo nodes share one and the same program, so editing one of them changes the others too — but each copy keeps its own position, variables, lifetime and so on while the program runs.

  • Making a Compo node
  1. Select the nodes you want to bundle together.
    To select several at once, double-click and drag.
    On the second click, keep the button down and drag out a selection box.
    On a phone it feels like “tap, tap-and-hold, sweep”.
    (In this sample the player is on the left, and the boxed area is the program for one enemy that chases the player.)



  2. With several nodes selected, press and hold any one of them to open the menu. Choose “MAKE COMPO” and confirm with “Yes”.




  3. The nodes have become a single Compo node called “C1”.


  4. Press and hold C1 (or double-click it) to step inside and edit the Compo in its own NodeEditor.
    The wires that ran into the Compo now appear as OUT nodes named “C1 1” and “C1 2”.

    Press “MENU” on the right and the left-hand column now holds the Compo commands.
    “Duplicate” makes a copy of this Compo node.
    The “PARENT” button at the bottom right leaves this NodeEditor and returns to the one above it.



  5. Back in the parent NodeEditor you can see that there are now several Compo nodes.
    We want “C1 (2)” to receive the same input, so wire it up the same way.



  6. Press “LAYOUT” and position each Compo where you want it.


  7. Press Play “▶” and you have several enemies, each moving on its own.

  8. To make a lot of copies at once, select the Compo nodes together, press and hold one of them and choose “Duplicate”.
    When every Compo needs the same value, IN and OUT nodes are the convenient way to deliver it.


  • Compo nodes and instances

    When two Compo nodes hold the same program, so that editing one changes the other, we say the two nodes are instances of each other; duplicating a Compo is “creating an instance of it”.
    Compo nodes with the same Compo number are instances of each other and share one program.
    (Breaking that link is called Unique, and you will find it in the Compo flick menu. See below)

    The number after the C tells you which Compo it is: the same number means instances of the same Compo.
    “C1 (1)” and “C1 (2)” are instances of each other.
    “C1 (1)” and “C2 (1)” are different Compos and are not related.
    The number in brackets simply distinguishes the copies of one Compo.

    Even when Compos are instances of each other, every parameter is handled separately during Play.
    Spawning and destruction, positions, and the count, var and array nodes inside each Compo all keep their own values.

  • The MENU inside a Compo node


    Duplicate and Delete: duplicate or delete the Compo node.

    Unique    : breaks this Compo’s link to its instances. Use it when you want to take a copy of a Compo and turn it into a different enemy. The copy is given a new Compo number.

    Expand    : moves the nodes inside the Compo you are editing back out into the main NodeEditor, and the Compo itself disappears. It is the opposite of Make Compo. Compos that are instances of this one are not expanded with it.

  • Compo nodes with IN and OUT nodes

    A Compo node has only two input and two output ports, but IN and OUT nodes let you add more.
    IN and OUT nodes have a Compo number in their properties, so you can deliver a value to one specific Compo.


    Inside a Compo you can use an IN node with no Compo number.
    Inside a Compo you cannot use an OUT node with no Compo number, because two identical OUT nodes are not allowed.

    Take care: an IN or OUT node with a Compo number means something completely different depending on whether it sits inside or outside the Compo.
    In the picture above, the blue “IN node: C1, index 2” appears both inside and outside the Compo, and the two are not the same. The one inside is wired to the Compo’s output 2, while the one outside is wired to the Compo’s input 2 and hands its value to the “OUT node: C1, index 2” inside.

  • The Enable input and output of a Compo

    When you use a Compo node as a character, the Enable input and output control when that character appears and disappears.

    The Enable output is 1 while the character exists and becomes 0 once it is destroyed.

    When the Enable input changes from 0 to 1 (or any non-zero value), the program inside the Compo starts and the character becomes active. It stays alive only while that input remains non-zero: if the input returns to 0, or the character is destroyed, it disappears.
    With nothing connected to the Enable input it behaves as if 1 were connected all along.

    Even a character that has disappeared comes back from its initial state when the input goes from 0 to non-zero again.

  • One parent per Compo node

    Inside a Compo, the parent–child chain of objects must not contain more than one top-level parent object. Building two characters inside a single Compo node is not supported.
    Two parents are fine as long as both share a common parent above them.
    Having no object node at all (and therefore no parent) is fine too.


  • Nodes that cannot be created inside a Compo

    BG, Setting, Stick, Button, Screen and OnBreak cannot be created inside a Compo.

8. Letting other people play your program

Just share a URL and anyone can play what you made.
Opening the URL starts straight in the Play view, so they need to know nothing about nodegram.

https://daisuqe.github.io/nodegram/?url=

followed by the address where your program is stored — that is all. 

Example:
https://daisuqe.github.io/nodegram/?url=https://example.com/mygame.json

Step by step:
1. Save your game as a .json file on your PC or phone with MENU > SAVE > EXPORT.
2. Upload the .json file you saved to Dropbox or a similar online file service, then copy the link to it (usually via something like “Copy link”).
3. Take https://daisuqe.github.io/nodegram/?url=, add the address where your program is stored, and open the whole thing in your browser.

Google Drive cannot be used for the URL, because browser restrictions stop an app from reading its files directly (a CORS restriction).

9. Specifications

9-1. 2D only

nodegram is 2D only. There are two axes: X (positive to the right) and Y (positive upwards). Turn Dynamics on in the Setting node and characters fall towards the bottom of the screen.
For a top-down game, either turn Dynamics off in the SETTING node or set the overall gravity to 0.

9-2. FPS

Choose a target frame rate of 60 or 30 on the SETTING node (60 by default). Both node evaluation and physics run at that rate. If a program gets too heavy, Play slows down and the real frame rate falls below the setting.

9-3. Dynamics (physics)

Objects such as Rect, Circle, Character and Shot can be given a physics mode (Dynamics). The behaviour is close to Unity’s Rigidbody2D.

Mode Behaviour
Off No physics. The node inputs (X,Y) simply move the object.
Static An immovable wall or floor. Gravity and collisions do not move it.
Dynamic Moves physically under gravity and collisions. The node’s X/Y inputs are applied as a force.
Kinematic Gravity and collisions do not move it, but node inputs can, and it still collides with and pushes Dynamic objects.

There is no density setting; everything is treated as roughly the density of wood.

9-4. SortingLayer (draw order)

Each object’s SortingLayer (0–100, 50 by default) decides the stacking order in the Play view. The higher the number the closer to the front it is drawn. BG (the background) is always furthest back.
Objects with the same value are drawn in the order they were added.

9-5. Coordinates

  • X is positive to the right and Y positive upwards. The centre of the Layout view is the origin (0,0).
  • Angles are in degrees and counter-clockwise is positive. 0° is right (X+), 90° is up (Y+), 180° is left (X−) and 270° is down (Y−). ANGLE POS, POS ANGLE, GetRot, ROTATE and an object’s Angle property all follow this convention.
  • An object’s Coord property changes what the X/Y node inputs mean.
    • WORLD: the input is an absolute position (relative to the parent, if the object has one).
    • LOCAL: the input is an offset from where the object was originally placed. With a parent set, the offset from the parent is included as well (parent coordinates).
  • For the coordinates of 3D objects see 9-11. 3D objects.

9-6. Resolution

The area shown during Play is the size of the grey rectangle in Layout.
The orientation (Horizontal or Vertical) is set on the SETTING node — not in the Setting menu — and the view is fitted to the size of the actual screen.
For a fixed resolution, use ScreenSize on the Setting node.

9-7. Tag

A Tag is a group.
You might tag every small enemy “Enemy_tiny”, for example, or use “bg_destroyed” and “bg” to tell destructible scenery from the rest.
The Shot, OnBreak, Rect, Circle and Character nodes all use Tags.


9-8. Working with nodes


  • An input port accepts several wires at once, and the node receives their sum. In the picture, the topmost port receives 10+20 = 30.

  • A parent–child connection between nodes (from the port on top to a port underneath) is used for more than moving objects together: it also expresses a relationship.
    That is how a Texture node is tied to an object node, an OnBreak node to the object it watches, and an Array node to a Line node.
    Normally a parent can have several children, but a child can have only one parent.
    The Texture, OnBreak and Array nodes are the exception: they can each have several parents.


9-9. What happens in one frame

All nodes are processed at the same time.
The order in which you created them never changes the result.

Object nodes and the like are processed once per frame.
Nodes that remember a value — Counter, Var, Trigger, Random, Array — are likewise updated only once per frame.
Arithmetic nodes such as + and × remember nothing, so they are evaluated whenever their value is needed.
Even so, if arithmetic nodes form a loop, each node is still processed only once within a frame.

9-10. UNDO / REDO

MENU’s UNDO / REDO undo and redo node creation, deletion, movement, wiring, property changes and so on. You can go back up to 50 steps.

The TEXTURE, LINE and SEQUENCER editors each keep their own undo history; use the ◁ / ▷ buttons inside the editor. The LINE editor and SEQUENCER also go back 50 steps, while TEXTURE varies with the texture size.

Note that running Play is not something that can be undone, and neither is saving or loading.

9-11. 3D objects


nodegram has two ways to show a 3D object: Polygon and ARRAY + LINE (3D view). Both are created only by importing an .obj file — you cannot make them from CREATE NEW NODE.

nodegram itself, however, is strictly a 2D platform. A 3D object is simply a way of using a 3D-looking image as 2D material, and like every other 2D object its draw order comes from its Sorting Layer setting. Polygon nodes that share a Sorting Layer are processed together as one 3D scene, so they overlap each other correctly in depth.

3D objects have a Z coordinate. The screen plane is z=0, further away is +z and towards the viewer is −z. The distance from the viewpoint to the screen, and the height of the viewpoint, are set on the Setting node.
You can still set up parent–child relationships with 2D objects, but z=0 is recommended when you do.

To draw with LINE (3D view), fill the ARRAY attached to the LINE node with a run of x,y,z triples. Everything up to a (9999,9999,9999) separator is joined into one continuous line, and what follows starts a new one (the format is x,y,z, x,y,z, … 9999,9999,9999, x,y,z, … 9999,9999,9999). An ARRAY can have several LINE nodes as parents.

10. Things to know

  • On a phone:
    Adding a nodegram shortcut to your home screen lets you use it like an app. But just as with an app, deleting it (removing the home-screen shortcut) will very likely delete your saved data. Use Export to keep finished programs as separate files.

    On some phone browsers the display or the touch positions can end up misaligned.
    If that happens, quit nodegram, close the task (this is not the same as deleting the app), hold the phone firmly in landscape and start it again.
  • Auto-save:
    While “auto save” is on in the save screen, the file you last used is overwritten every minute. To keep a separate copy, use Save and give it a new name.
